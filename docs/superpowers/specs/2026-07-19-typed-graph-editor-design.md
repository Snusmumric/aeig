# AEiG — Дизайн: браузерный редактор типизированных графов с метамоделями и валидацией

**Дата:** 2026-07-19
**Статус:** согласован (дизайн), ожидает финальной вычитки перед планом реализации

## 1. Обзор

Браузерное приложение для **создания, хранения и отображения произвольных типизированных графов**. Ключевые возможности:

- бесконечное поле с эвристической раскладкой, минимизирующей нахлёсты;
- вершины и рёбра со свойствами, где **тип** — ключевое свойство;
- **метамодели** — наборы типов вершин/рёбер + конструкционные правила; проекция подграфов по метамодели;
- **правила валидации** структуры графа на опубликованном языке (openCypher), а не на самодельном;
- отображение рёбер выбранного типа как **вложения** вершины в вершину (containment), а не линией;
- разные фигуры/цвета по типам (одинаковые у одинаковых типов);
- ориентированные и неориентированные графы;
- раздвигание сильносвязанных компонент по требованию, ручное перемещение элементов, сохранение конкретной раскладки.

### Зафиксированный стек

| Слой | Выбор |
|---|---|
| Frontend | React + TypeScript, рендер графа — **React Flow** (`@xyflow/react`) |
| Backend | **Go**, REST/JSON API |
| Графовое хранилище | **Neo4j** (протокол Bolt, официальный Go-драйвер) |
| Хранилище метаданных | **PostgreSQL** |
| Модель данных | Labeled Property Graph |
| Язык правил | **openCypher** (pluggable-движок на будущее — напр. Datalog) |
| Раскладка | ELK (elkjs) + d3-force (анти-нахлёст) |

### Границы решений (принято в брейншторме)

- Развёртывание: **клиент + бэкенд с БД сразу**, многопользовательский режим, серверная валидация.
- Метамодель: **два слоя** — живая схема + Cypher-правила, **мягкий enforcement** (strict-режим опционален).
- Масштаб: **мало на экране** (сотни узлов в подграфе), **много в БД** (стор может быть больше RAM).
- Конкурентность: **оптимистичная** с версионированием (без CRDT/real-time со-редактирования).
- Подграфы: **проекция по типам метамодели** (основное) + сохранённые Cypher-представления (расширение).
- Containment: **полный** — рекурсивное вложение, сворачивание/разворачивание, внешние рёбра у вложенных узлов.
- Раскладки: **много именованных** на граф/подграф, шаринг.
- Аутентификация: **на старте отсутствует** (доверенная внутренняя среда), добавляется позже.

## 2. Высокоуровневая архитектура

Три яруса:

- **Frontend (React + TS)** — канвас React Flow, редактор метамоделей, редактор Cypher-правил, панель результатов валидации. Общается с бэкендом по REST/JSON. К Neo4j напрямую **не обращается** (безопасность, валидация, версионирование — на сервере).
- **Backend (Go)** — REST API и доменная логика: CRUD графов, метамодели/схема, живая мягкая валидация схемы, хранение и исполнение Cypher-правил, проекция подграфов, персист раскладок, версионирование. К Neo4j — по Bolt. **SCC (алгоритм Тарьяна)** вычисляется на бэкенде на запрошенном подграфе.
- **Хранилища:**
  - **Neo4j** — экземпляры графов (вершины/рёбра с типом и свойствами). Много графов в одном инстансе через свойство `graphId` + индекс (без Enterprise multi-database).
  - **PostgreSQL** — метаданные приложения: определения метамоделей, Cypher-правил, представлений, именованные раскладки, история версий; позже — пользователи и шаринг.

**Обоснование разделения хранилищ:** данные графа естественно ложатся на графовую БД и обходы/Cypher; метаданные (списки, версии, права, документы определений) — реляционные/документные, выигрывают от транзакций и простого перечисления. Альтернатива (всё в Neo4j, один датастор, проще ops) отклонена, т.к. версии/шаринг/списки в Neo4j моделируются хуже.

```
┌────────────────────┐      REST/JSON      ┌────────────────────┐
│  React + TS        │ ─────────────────►  │  Go backend        │
│  React Flow канвас │                     │  доменная логика   │
│  редакторы MM/rules│ ◄─────────────────  │  SCC (Тарьян)      │
└────────────────────┘                     └─────────┬──────────┘
                                        Bolt │        │ SQL
                                    ┌─────────▼─┐  ┌───▼────────┐
                                    │  Neo4j    │  │ PostgreSQL │
                                    │ графы     │  │ метаданные │
                                    └───────────┘  └────────────┘
```

## 3. Модель данных

### 3.1 Экземпляры графов (Neo4j)

- **Node**: `graphId`, `id`, `type`, `properties` (map). Позиции здесь **не** хранятся — они в раскладке (см. §7).
- **Edge** (Neo4j relationship): `type`, `properties`. Направленность и признак «рисуется как containment» — свойства *типа ребра* (в метамодели), не самого ребра.
- Вложение выражается ребром containment-типа; родитель узла для рендера **выводится** из этих рёбер, отдельно не дублируется.
- Индекс по `graphId` (+ по `graphId, type`) для быстрой выборки подграфа.

### 3.2 Метамодель — система типов (PostgreSQL)

- **NodeType**: имя, схема свойств (`name → {type, required, enum?}`), стиль (фигура, цвет).
- **EdgeType**: имя, допустимые типы источника, допустимые типы цели, кардинальности (min/max по концам), `directed | undirected`, `isContainment`, стиль.
- **Metamodel**: именованный набор `NodeType` + `EdgeType` + Cypher-правил + конструкционных ограничений.
  - Тип принадлежит метамодели.
  - Граф объявляет применимые метамодели и может охватывать **несколько** метамоделей.
  - **Проекция по метамодели = фильтр графа по её типам.**

## 4. Метамодель и правила — два слоя

### 4.1 Слой 1 — живая схема (мягкий enforcement)

Проверяется на каждой мутации: типизация концов ребра, кардинальности, required/типизированные свойства, правила вложения (напр., какие пары типов допускают containment, отсутствие циклов вложения).

- Оценщик на Go смотрит **локальную окрестность** (вершина + её непосредственные рёбра) — дёшево.
- Зеркалится на клиенте для мгновенной подсветки при рисовании.
- Возвращает **предупреждения**, не блокирует. Опциональный **strict-режим** запрещает недопустимые действия.
- Ограничения — декларативные в определении метамодели (JSON).

### 4.2 Слой 2 — Cypher-правила (по требованию)

Правило = сохранённый Cypher-запрос, возвращающий **нарушения**, + метаданные (имя, сообщение, `severity`, `scope` = метамодель/граф).

- Бэкенд исполняет правило в Neo4j со scope по `graphId`, в **read-only** транзакции, с лимитами; отдаёт список нарушений → фронт подсвечивает элементы.
- Интерфейс движка правил **pluggable** — позже можно добавить Datalog-диалект (мост «граф→факты» невелик).

**Примеры (соглашение: запрос возвращает нарушения; пусто → валидно):**

```cypher
// «Все вершины типа A достижимы из вершин типа B»
MATCH (a:A {graphId:$graphId})
WHERE NOT EXISTS { MATCH (b:B {graphId:$graphId})-[*1..]->(a) }
RETURN a AS violation
```

```cypher
// «Значение свойства p вершины A встречается хотя бы в одной другой
//  вершине, достижимой из A по рёбрам метамодели X»
MATCH (a:A {graphId:$graphId})
WHERE NOT EXISTS {
  MATCH (a)-[r*1..]->(other)
  WHERE all(e IN r WHERE e.mm = 'X') AND other <> a AND other.p = a.p
}
RETURN a AS violation
```

## 5. Подграфы и представления

- **Основное:** проекция по набору типов метамодели (+ опционально фокус-вершина и глубина N шагов).
- **Расширение:** сохранённые Cypher-представления (произвольный критерий).
- Представление отдаёт подграф (сотни узлов), который грузится в канвас.

## 6. Рендер, раскладка и взаимодействие (React Flow)

### 6.1 Узлы и рёбра

- Каждый `NodeType` → кастомный React-компонент; фигура/цвет/лейбл — из стиля типа. Карта `type → style` гарантирует одинаковое отображение одинаковых типов. Свойства узла — компактно внутри узла + подробно в боковой панели.
- Directed-рёбра — со стрелкой, undirected — без (по флагу типа ребра).
- Containment-типы **не рисуются линией**: целевой узел лежит внутри исходного (React Flow parent-узлы, рекурсивно), со сворачиванием/разворачиванием; у вложенных узлов допустимы обычные рёбра наружу.

### 6.2 Пайплайн раскладки

- **ELK (elkjs)** — основной движок: `layered` (Sugiyama) для направленных/DAG-проекций, `force`/`stress` для общих графов, вложенная compound-раскладка внутри контейнеров.
- **Проход анти-нахлёста** — `forceCollide` (d3-force) поверх/через spacing ELK → эвристика «без нахлёстов».
- **Ручное перемещение:** пользователь двигает узлы, позиции персистятся.
- **«Раздвинуть SCC»:** алгоритм Тарьяна по текущему подграфу → к выбранному сильносвязному кластеру применяется усиленное отталкивание / локальный re-layout, чтобы разнести его члены.

### 6.3 Раскладки

- Несколько **именованных** раскладок на граф/подграф; хранятся позиции узлов + состояние свёрнутости контейнеров + вьюпорт.
- Автораскладку можно запустить заново; ручные правки сохраняются поверх.
- При загрузке берётся сохранённая раскладка — повторного авто-расчёта нет.

## 7. Версионирование и конкурентность

- Оптимистично: у графа счётчик версии; мутация шлётся с `baseVersion`; конфликт → `409` + клиент примиряет (показ расхождения, повтор).
- История версий — в PostgreSQL (журнал изменений на граф).
- Раскладки версионируются **отдельно** от структуры графа: правка позиций ≠ правка данных графа.

## 8. API (React ↔ Go, REST/JSON)

| Ресурс | Назначение |
|---|---|
| `graphs` | CRUD, версия графа |
| `graphs/{id}/nodes`, `/edges` | батч-мутации с `baseVersion` |
| `metamodels` | CRUD типов и конструкционных ограничений |
| `rules` | CRUD + `POST /rules/{id}/run?graphId=…` → нарушения |
| `views` | проекция по типам и Cypher-представления → подграф |
| `layouts` | CRUD именованных раскладок |
| `validate` | живой слой схемы для мутации; запуск набора Cypher-правил |

Фронт **никогда** не шлёт сырой Cypher напрямую в Neo4j — только через типизированные ручки Go. Пользовательский Cypher (правила/представления) проходит серверную обвязку: scope по `graphId`, лимиты, read-only транзакция.

## 10. Открытые вопросы / точки расширения

- Значение аббревиатуры **AEiG** (имя проекта) — уточнить, влияет только на брендинг.
- Конкретные лимиты и таймауты для пользовательского Cypher (защита от тяжёлых запросов).
- Формат импорта/экспорта (GraphML vs собственный JSON) — фаза «Позже».
- Модель прав при появлении аутентификации (per-graph роли viewer/editor; при необходимости — команды/RBAC, OIDC/SSO).
- Пороговые размеры подграфа, при которых включать агрегацию/LOD (пока считаем «сотни» комфортными для React Flow).
