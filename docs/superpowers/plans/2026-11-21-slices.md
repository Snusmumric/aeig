# Slices (v3.1) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Named per-graph slices (PG identity + description) with membership as the `sliceIds` system property on `:Element`, full UI (management panel, node/edge context menus, active-slice view) and a persisted per-visualization slice filter.

**Architecture:** Migration `0007` creates `slices`, `0008` adds `layouts.visible_slices`; `postgres.SliceRepo` (identity CRUD) + `neo4j.SliceMembershipRepo` (property ops, preserve-on-upsert) composed by `SliceService`; `GET /subgraph` exposes `GraphNode.sliceIds` as a typed system field; frontend gains `visibleSlices` viz state integrated into `filterFlow`, a `SlicePanel`, and context menus for membership.

**Tech Stack:** Go (chi, pgx, golang-migrate, testcontainers), React 19 + @xyflow/react 12, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-21-slices-design.md` (v3.1 — binding in full, incl. Approaches, Preserve pattern, Slice filter section, UI details).

## Global Constraints

- Storage per spec v3: PG `slices (id, graph_id CASCADE, name, description NOT NULL DEFAULT '', UNIQUE(graph_id,name))` — **no created_at**; Neo4j `:Element.sliceIds [uuid]` — the 4th system property (`reservedKeys` + `userProps` strip), exposed ONLY as the typed `GraphNode.sliceIds` response field.
- **Preserve pattern (critical)**: `UpsertNode` keeps `SET x = $props` semantics (omitted user props still deleted) but captures and restores `sliceIds` in the same query; `UpsertEdge`/`DeleteNode` unchanged.
- Membership ops are single-statement Cypher expression SETs (add: `coalesce(e.sliceIds,[]) + $sid`; remove: filter); unknown ids skipped; idempotent.
- Slice delete = PG delete + best-effort synchronous sweep; failure still 204; no background cleanup. Rename/description = PG only. Slice edits never bump `graphs.version`.
- API name-addressed (see spec table incl. PATCH and `{name, description?, nodeIds?}` on create); create-with-nodes is best-effort cross-store: slice row first, membership add second; response reports the actual nodeCount (my call — cross-store atomicity is impossible; the spec's "atomically" is read as "one request").
- Slice filter: node hidden iff ANY of its sliceIds is in the hidden set; membership-free nodes always visible; edges follow endpoints; composes AND with type filters; `visibleSlices` partial-PUT (absent=unchanged, present=full replace), autosave family; `NULL` = all visible.
- UI: SlicePanel (list+counts+description, create, inline rename, delete confirm, active slice, «Только срез», visibility checkboxes with «Все/Ни одного» normalization), node context menu (per-slice checkmarks, toggle, «новый срез…»), edge context menu (adds both endpoints, disabled when both already members). View state (active slice, «Только срез») ephemeral; filter persisted. Context menus = plain DOM overlays (`onNodeContextMenu`/`onEdgeContextMenu`), close on Escape/click-outside.
- No new Neo4j labels/rel types anywhere. archgen: +6 nodes (`tbl-slices`, `fld-slices-id/graph-id/name/description`, `prp-element-sliceids`, `ent-slice`) / +9 edges (has_field×4, stored_in, references, has_property, persisted_as, belongs_to), stable ids, append at end.
- Conventions: TDD RED→GREEN; backend `make test` / `go test -tags=integration ./...`; frontend `npm test` / `npx tsc -b` / `npm run lint`; conventional commits; graph refresh deferred to the controller task; dev stack runs with auto-picked PG_PORT (fixed in dev.sh).
- Parallel waves (user-approved): Wave A = Tasks 1–4 (backend/), Wave B = Tasks 5–9 (frontend/ + scripts/ + seed/). Disjoint trees; `--no-verify` + pathspecs; index.lock retry; wave ledgers.

## Review Focus

1. Upsert preserves `sliceIds` AND still deletes omitted user props (mutation-semantics regression) → neo4j integration test (Task 3).
2. `sliceIds` never surfaces as a user property, but DOES as the typed GraphNode field → both assertions in one test (Task 3).
3. Filter semantics: two-slice node visible while either checked; membership-free always visible; edge follows endpoints; `null` = all → filterFlow/useGraph tests (Task 6).
4. `visibleSlices` persistence: absent=unchanged / present=replace; autosave includes it; viz load restores → repo integration + GraphEditor test (Tasks 2, 8).
5. Rename collision → 409; delete → 204 with sweep best-effort; stale filter ids inert → service/httpapi + panel tests (Tasks 4, 7).
